# راهنمای سریع (۱۰ دقیقه تا اتصال واقعی)

این اپ یک **رله‌ی مسیر (VPN)** است، نه یک دکمه‌ی جادویی. برای اینکه کاری انجام دهد، به یک سرور
WireGuard نیاز دارد که **کلید عمومی گوشی شما روی آن ثبت شده باشد**. سه حالت دارید:

| حالت | چه زمانی | سختی |
| --- | --- | --- |
| الف) یک VPS خودتان (پیشنهادی) | مسیر پایدار و کنترل‌شده می‌خواهید | ~۱۰ دقیقه، یک‌بار |
| ب) کانفیگ WireGuard آماده دارید | از هر ارائه‌دهنده/شرکت/دوستی `wg0.conf` دارید | ~۱ دقیقه |
| ج) رله‌ی تیمی/عمومی دارید | اپراتور، کلید عمومی شما را ثبت می‌کند | ~۲ دقیقه |

بدون یکی از این‌ها، اپ بالا می‌آید ولی دکمه‌ی Connect خطا می‌دهد (این رفتار درست است، نه باگ).

---

## گام ۰ — نصب APK

فایل: `dist/vz-network-booster-debug.apk` (۲۳٫۶ MB، امضای debug)

- انتقال به گوشی (کابل، Telegram Saved Messages، Drive…) → نصب → اجازه‌ی «نصب از منابع نامعلوم».
- یا از GitHub Actions: تب Actions → آخرین اجرای سبز `Android CI` → Artifact `vz-network-booster-debug-apk`.
- نام بسته: `com.vz.networkbooster.debug`

---

## گام ۱ — آماده کردن رله

### حالت الف) VPS خودتان (Ubuntu/Debian، root)

```bash
# روی سرور
scp scripts/relay-setup.sh root@SERVER_IP:/root/
ssh root@SERVER_IP
sudo bash /root/relay-setup.sh --name fra-01 --region eu --capacity 150
```

خروجی، یک JSON چاپ می‌کند (`/root/vz-server-bundle.json`) که باید در اپ چسبانده شود.
بدون `--device-public-key` هم می‌شود اجرا کرد؛ کلید گوشی را بعداً اضافه می‌کنید (گام ۳).

### حالت ب) کانفیگ آماده دارید

فقط فایل `wg0.conf` (یا متن کانفیگ) را داشته باشید — همان را در گام ۴ در اپ می‌چسبانید؛
اپ کلید خصوصی داخل کانفیگ را **رمزنگاری‌شده روی همان گوشی** نگه می‌دارد.

### حالت ج) رله‌ی شخص دیگر

از اپراتور بخواهید کلید عمومی شما را به‌عنوان peer ثبت کند:
`wg set wg0 peer <DEVICE_PUBLIC_KEY> allowed-ips 10.66.0.2/32`
سپس bundle (endpoint + serverPublicKey + address) را از او بگیرید.

## اگر همین حالا یک فایل WireGuard داری: کدام نوع است؟

فایل را باز کن و ببین `Endpoint` دارد یا `ListenPort`:

| نشانه در فایل | نوع فایل | مسیر درست |
| --- | --- | --- |
| `Endpoint = host:port` دارد، `ListenPort` ندارد | **کانفیگ کلاینت** (معمولاً از ارائه‌دهنده/شرکت) | Relays → Add relay → **Choose file…** → فایل را انتخاب کن → Import → Connect. همین. |
| `ListenPort` و/یا `PostUp/PostDown` دارد و `Endpoint` ندارد | **کانفیگ سرور (رله)** | کلید خصوصی سرور را **هرگز** داخل گوشی نگذار. اسکریپت زیر را روی سرور بزن، سپس bundle را در اپ بچسبان. |

برای حالت دوم، روی سرور:

```bash
scp scripts/server-to-bundle.sh root@SERVER_IP:/root/
ssh root@SERVER_IP
# ۱) کلید عمومی گوشی: اپ → Settings → Device identity → Copy public key
sudo bash /root/server-to-bundle.sh --name fra-01 --region eu \
     --device-public-key <DEVICE_PUBLIC_KEY> --apply
```

خروجی: یک JSON (که در اپ می‌چسبانی) و ثبت peer گوشی روی رله (`wg set … && wg-quick save`).
اسکریپت هیچ تغییری در ساختار کانفیگ سرور نمی‌دهد و کلید خصوصی سرور را چاپ نمی‌کند.

اگر اشتباهی کانفیگ سرور را در اپ بچسبانی، اپ آن را رد می‌کند و همین توضیح را نشان می‌دهد
(باگ/خطای مبهم نمی‌بینی).

## گام ۲ — کلید عمومی گوشی را بردارید

اپ → تب **Settings** → بخش **Device identity** → دکمه‌ی **Copy public key**.

این کلید را در گام ۳ روی سرور ثبت می‌کنید. کلید خصوصی هیچ‌جا نمایش داده نمی‌شود.

---

## گام ۳ — ثبت کلید روی سرور (فقط حالت الف/ج)

```bash
sudo wg set wg0 peer <DEVICE_PUBLIC_KEY> allowed-ips 10.66.0.2/32
sudo wg-quick save wg0
sudo wg show            # باید peer را ببینید
```

پورت UDP را هم باز کنید (اگر ufw فعال است اسکریپت خودش باز می‌کند؛ در پنل ابری هم
Security Group را چک کنید).

---

## گام ۴ — رله را در اپ اضافه کنید

تب **Relays** → **Add relay** → در فیلد متن، JSON را بچسبانید:

```json
{
  "name": "fra-01",
  "region": "eu",
  "endpoint": "SERVER_IP:51820",
  "serverPublicKey": "<PUBLIC KEY سرور>",
  "address": "10.66.0.2/32",
  "allowedIps": "0.0.0.0/0, ::/0",
  "dns": "1.1.1.1",
  "mtu": 1420,
  "capacity": 150,
  "dedicated": true
}
```

- **حالت ب**: همان‌جا متن کامل `[Interface]/[Peer]` را بچسبانید (JSON لازم نیست).
- سپس **Check health**. اگر رله probe target نداشته باشد وضعیت **unverified** است — یعنی
  «اندازه‌گیری نشده»، نه «سریع». برای اندازه‌گیری واقعی، یک سرویس TCP روی سرور بالا بیاورید و در
  bundle بنویسید `"probeHost": "...", "probePort": 9000`.

---

## گام ۵ — بازی را انتخاب کنید

تب **Games** → روی **PUBG Mobile Global** بزنید (`select`).
پکیج داخلی آن `com.tencent.ig` است؛ اگر نسخه‌ی دیگری دارید، با **Add game** پکیج خودتان را اضافه کنید.

**نکته‌ی مهم این تب:** اگر می‌خواهید کیفیت مسیر بازی اندازه‌گیری شود، یک probe target واقعی
اضافه کنید (host:port سرور منطقه‌ای بازی که می‌شناسید). بازی‌ها به probe ناشناس پاسخ نمی‌دهند، پس
اپ عدد جعلی نمی‌سازد.

---

## گام ۶ — اتصال

تب **Home** → **Connect** → اندروید پنجره‌ی اجازه‌ی VPN نشان می‌دهد → **OK**.

کارت وضعیت باید برود روی `Tunnel active` + نام رله + uptime + ترافیک.
اگر split tunnelling روشن باشد (پیش‌فرض: «game apps only»)، فقط پکیج‌های بازی + خود اپ از تونل
عبور می‌کنند و بقیه‌ی گوشی دست‌نخورده می‌ماند.

---

## گام ۷ — اندازه‌گیری قبل/بعد (تنها قیاس معتبر)

تب **Measure**:

1. **قبل از اتصال** (تونل قطع) روی target بزنید → گزارش با مسیر `direct`.
2. **بعد از اتصال** همان target را بزنید → گزارش با مسیر `tunnel:fra-01`.

اعداد:
- `avg/min/max` = RTT واقعی دست‌دادن TCP (یا UDP اگر پاسخ بدهد)
- `jitter` = میانگین قدرمطلق اختلاف نمونه‌های متوالی
- `loss` = درصد تلاش‌های بی‌پاسخ

اگر مسیر رله بدتر بود، همان عدد بدتر در اپ دیده می‌شود — این هدف طراحی است: هیچ ادعای
«کاهش تضمینی پینگ» وجود ندارد.

---

## گام ۸ — بهینه‌سازی مسیر

تب **Measure** → **Run optimizer** (یا دکمه‌ی Optimize route در Home):
رله‌ها یکی‌یکی بالا می‌آیند، از **داخل همان تونل** اندازه‌گیری می‌شود و بهترین مسیر انتخاب می‌شود.
لاگ مرحله‌به‌مرحله در همان کارت دیده می‌شود.

## عیب‌یابی سریع

| نشانه | علت | راه‌حل |
| --- | --- | --- |
| `VPN permission denied` | پنجره‌ی اجازه رد شده | Connect را دوباره بزنید و OK کنید |
| `backend: VPN_NOT_AUTHORIZED` | اجازه‌ی VPN داده نشده | همان بالا؛ اگر Always-on VPN دیگری فعال است خاموشش کنید |
| خطای فوری در Connect | endpoint اشتباه / کلید نادرست | `wg show` روی سرور، پورت UDP، و کلید عمومی دستگاه |
| تونل بالا می‌آید ولی بازی وصل نمی‌شود | پکیج بازی در پروفایل نیست | Games → Add game با پکیج درست؛ یا split tunnelling را خاموش کنید |
| `no TCP handshake completed` | host/port اشتباه یا فیلتر | target واقعی دیگری امتحان کنید |
| `no UDP reply` | طبیعی است | بازی‌ها به UDP ناشناس پاسخ نمی‌دهند؛ از TCP استفاده کنید |
| وضعیت رله `unverified` | probe target ندارد | probeHost/probePort را در bundle اضافه کنید |
| اینترنت بعد از اتصال قطع می‌شود | رله NAT/forward ندارد | `sysctl net.ipv4.ip_forward` و قاعده‌ی MASQUERADE را چک کنید |

## چک‌لیست ۵ خطی

1. APK نصب شد؟
2. رله بالا است و `wg show` روی سرور handshake را نشان می‌دهد؟
3. کلید عمومی گوشی روی سرور به‌عنوان peer ثبت شده؟
4. Relays → bundle اضافه شد و Check health خطای `failing` ندارد؟
5. Home → Connect → Measure (before/after)؟
