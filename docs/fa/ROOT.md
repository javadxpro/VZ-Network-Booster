# حالت روت (اختیاری)

گوشی روت‌شده چند چیز را ممکن می‌کند که بدون روت **غیرممکن** است. هیچ‌کدام «کاهش جادویی پینگ» نیست؛
همه‌شان یا دقت اندازه‌گیری را بالا می‌برند یا یک عامل شناخته‌شده‌ی نوسان/قطعی را برمی‌دارند.

## آنچه روت اضافه می‌کند

| قابلیت | چه کاری می‌کند | اثر واقعی | ریسک |
| --- | --- | --- | --- |
| **پروب ICMP (ping واقعی)** | اجرای `/system/bin/ping` با `su` و پارس کردن خروجی (RTT، loss، jitter) | اندروید اجرای ping را برای اپ‌های معمولی می‌بندد؛ با روت عدد واقعی ICMP می‌گیرید | فقط اندازه‌گیری، بی‌خطر |
| **Wi-Fi power save off** | `iw dev wlan0 set power_save off` (یا `wifi_sleep_policy=2`) | یکی از منابع واقعی جهش تأخیر روی وای‌فای حذف می‌شود → jitter کمتر | مصرف باتری کمی بیشتر |
| **Whitelist در Doze** | `cmd deviceidle whitelist +com.vz.networkbooster...` | سرویس تونل در پس‌زمینه کشته نمی‌شود → reconnect کمتر | باتری کمی بیشتر |
| **BBR برای TCP** | اگر کرنل پشتیبانی کند: `bbr` | throughput بهتر روی لینک پرافت/بی‌کیفیت؛ **RTT را کم نمی‌کند** | تغییر موقت و بازگردانی‌شدنی |
| **drop_caches** | `sync; echo 3 > /proc/sys/vm/drop_caches` | آزادسازی یک‌باره‌ی page cache؛ روی گوشی کم‌رم وقتی بازی kill می‌شود مفید | اثر کوتاه‌مدت، بی‌خطر |

## آنچه روت **اضافه نمی‌کند** (و ادعا هم نمی‌شود)

- **کاهش تضمینی پینگ**: مسیر همان است که هست؛ روت فاصله‌ی جغرافیایی را عوض نمی‌کند.
- **بازنویسی خودکار مسیر بازی با iptables/ip rule**: پیاده‌سازی نشده. این کار نیاز به حالت
  «WireGuard کرنل + policy routing بر اساس UID» دارد و بدون تست روی دستگاه، احتمال قطع کامل شبکه‌ی
  کاربر را بالا می‌برد. به‌عنوان کار آینده ثبت شده است.
- **کشتن خودکار اپ‌های دیگر / تغییر CPU governor**: پیاده‌سازی نشد (خطر آسیب و ادعای بی‌پشتوانه).

## فعال‌سازی

1. روی گوشی، وقتی اپ برای اولین بار `su` را صدا بزند، Magisk/KernelSU از شما اجازه می‌گیرد → **Allow**.
2. اپ → **Settings** → کارت **Root mode** → **بررسی مجدد روت** (وضعیت باید `available` شود).
3. سوییچ‌های دلخواه را روشن کنید (Wi-Fi / Doze / BBR / drop caches / ICMP).
4. **اعمال** برای اجرای فوری، یا فقط سوییچ «استفاده از روت» را روشن کنید تا هنگام Connect اجرا شود.

## بازگردانی

- هنگام **Disconnect**، تغییرها خودکار برمی‌گردند (`iw ... power_save on`، حذف از Doze whitelist،
  بازگرداندن مقدار قبلی `tcp_congestion_control`).
- دکمه‌ی **بازگردانی** در همان کارت، دستی هم اجرا می‌کند.
- مقادیر اصلی (interface و congestion control قبلی) در SharedPreferences خصوصی اپ ذخیره می‌شوند.

## امنیت

- همه‌ی دستورها از یک **allow-list ثابت** می‌آیند؛ ورودی کاربر بدون اعتبارسنجی به shell نمی‌رسد
  (پکیج با `^[a-zA-Z0-9._]+$`، host با `^[A-Za-z0-9._:-]{1,253}$`، نام اینترفیس `^wlan[0-9]{1,2}$`).
- **کلید خصوصی WireGuard هرگز از این پوسته عبور نمی‌کند** (نه در آرگومان، نه در فایل موقت).
- خروجی دستورها بدون راز لاگ می‌شود و در UI هم فقط خلاصه‌ی هر مرحله دیده می‌شود.
- تایم‌اوت هر دستور ۳ تا ۸ ثانیه است؛ فرآیند معلق با `destroyForcibly()` بسته می‌شود.

## محدودیت‌های واقعی

- بعضی رام‌ها `iw` ندارند → اپ به `settings put global wifi_sleep_policy 2` برمی‌گردد و همین را
  در گزارش قدم‌ها می‌نویسد (تظاهر نمی‌کند که `iw` کار کرده).
- برخی کرنل‌ها BBR ندارند → گام با خطای صریح `kernel does not offer bbr` گزارش می‌شود.
- روی اندروید ۱۴+ بعضی سیاست‌های Doze با app-ops سخت‌گیرتر شده‌اند؛ اگر رد شود، همان را می‌بینید.
- ICMP به سرور بازی معمولاً پاسخ نمی‌گیرد (بازی‌ها ICMP را فیلتر می‌کنند)؛ برای سنجش **مسیر** و
  **رله** بهترین ابزار است، برای خود بازی از TCP/UDP استفاده کنید.
